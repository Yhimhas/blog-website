## 2. 技术路线与第一版边界

### 2.1 Vue 与 Nuxt 的关系

Vue 是前端框架，Nuxt 是基于 Vue 的应用框架；用 Nuxt 仍然是在编写 Vue 组件。本计划延续原方案的博客 SSR/SEO 目标，按以下顺序学习：

1. 第 1 周在现有 `frontend/blog-website` 中熟悉 Vue 3 Composition API、`<script setup lang="ts">` 和组件通信。
2. 第 3 周在 `frontend/site` 建立正式 Nuxt 前端，手动复用第一周的文章卡片等组件。第一周只做少量可迁移组件，不先实现整套 Vite 应用。
3. 此后只在 `frontend/site` 开发正式业务。现有 Vite 工程保留为学习参考，不再增加业务；不删除或覆盖它。

这是本次建议的学习安排，尚未执行迁移。Nuxt 负责路由、页面渲染和前端交互；Go 负责认证、文章、音乐、推荐及数据库访问。SSR 数据读取使用 Nuxt 的数据获取机制，避免服务端和客户端重复取数。参见 [Nuxt 数据获取](https://nuxt.com/docs/4.x/getting-started/data-fetching)。

### 2.3 第一版验收范围

- 首页、关于页、博客列表与详情、分类和标签、基础 SEO、响应式布局。
- 单站长登录；Markdown 草稿、受保护预览、编辑、发布和归档；不提供公开注册。
- 音乐清单和曲目管理；默认先手动录入官方 ID/链接。
- 经实测可用的官方嵌入方式，以及明确的官方跳转入口；持久布局中的播放器容器。
- 每天默认 3 首、所有访客一致的推荐；最近记录；定时执行、幂等、启动补偿和任务状态。
- 自托管 Debian 部署、HTTPS、自启配置、日志、备份恢复及运行说明。

来源自动同步是条件功能：只有实测官方能力适用才排入后续工作。第一版允许手动维护曲库、自动生成每日推荐。评论、访客登录、相册、个性化推荐、复杂动效、自制全曲音频播放器不列入本轮。

## 3. 每天两小时的工作方式

| 时间 | 做什么 | 当天留下什么 |
|---|---|---|
| 0–15 分钟 | 回顾昨天，阅读当天概念 | 用自己的话写 2–3 句解释 |
| 15–90 分钟 | 亲手实现当天一个小目标 | 小范围、能解释的改动 |
| 90–110 分钟 | 运行、检查成功路径和一个边界情况 | 实际结果或失败信息 |
| 110–120 分钟 | 记录进度、疑问和下一步 | 学习日志；适合时做一次自己的 Git commit |

每周第 7 天的两小时改为：20 分钟演示、60 分钟补缺口、25 分钟解释代码与 Review、15 分钟调整下周任务。提前完成时练习解释代码或补边界验证，不直接扩大功能。

卡住 20 分钟后，记录“预期结果、实际结果、完整报错、尝试过什么”，向助手求一个提示。环境安装或依赖问题占满当天时，该日就以定位问题为交付，业务任务顺延到复盘日或机动日。

## 7. 第一课：D01 的两小时任务

**目标：在已有 Vue 页面中展示站点标题和简介，并通过按钮控制简介显隐。** 本课不拆新组件、不接 API，不需要安装 Go。

### 7.1 第 0–15 分钟：读懂启动路径

打开以下文件并写出各自作用：

- `frontend/blog-website/package.json`：启动、构建、类型检查脚本和 Node 版本要求。
- `frontend/blog-website/index.html`：页面容器及脚本入口。
- `frontend/blog-website/src/main.ts`：创建并挂载 Vue 应用。
- `frontend/blog-website/src/App.vue`：根组件的逻辑、模板、样式。

当前 `package.json` 声明 Node 为 `^22.18.0 || >=24.12.0`。先检查本机版本是否满足；从当前文件读取要求，不照搬旧教程。

### 7.2 第 15–35 分钟：由你运行现有工程

在前端目录执行版本检查；依赖尚未安装时，选一种 package manager 安装，然后运行 `dev`。已有 README 使用 pnpm，你也可以使用 npm，但一个工程只维护一种对应锁文件，不混用。

这一步会按所选工具产生依赖目录、锁文件等正常产物。记录其用途；若遇到报错，把命令、工作路径、完整报错发给助手，不盲目删除锁文件或 node_modules 重试。

验收：浏览器能打开现有欢迎页面，终端没有阻止启动的报错。若环境在这一步卡住，当天先解决环境，下面的编码任务顺延。

### 7.3 第 35–90 分钟：你亲手写页面

只编辑 `frontend/blog-website/src/App.vue`：

1. 在逻辑区准备一个站点标题、一个简介文本和一个“是否显示简介”的状态。
2. 用模板显示标题，并根据状态显示或隐藏简介。
3. 放一个按钮，点击后切换状态；按钮文字随状态变化。
4. 写少量 scoped 样式，保证文字和按钮清楚即可。

需要查阅的概念：`<script setup>`、`ref`、插值、`v-if`、`@click`。参见 [Vue 响应式基础](https://vuejs.org/guide/essentials/reactivity-fundamentals.html)。

提示：普通固定文本可以是普通常量；需要触发界面更新的状态才需要响应式。先确定“哪些信息会变”，再选择写法。

### 7.4 第 90–110 分钟：验收

- 页面显示你自己填写的站点标题和简介。
- 连续点击按钮能正确显示/隐藏简介，按钮文案同步变化。
- 浏览器没有运行错误；用所选 package manager 执行现有 `build` 脚本通过。
- 能回答：“为什么显隐状态需要响应式？脚本中的 ref 和模板中的访问有什么区别？”

首次构建可能产生 `dist` 和类型检查缓存，属于正常可再生成产物，记录即可，不自动清理。

### 7.5 第 110–120 分钟：把成果交给助手 Review

提供实际结果、改动的文件和一个你最不确定的问题。助手会检查目标是否完成，并指出需要你自己修改的地方。

**D01 不要求精美设计。完成启动、理解状态、通过一次构建，就达到了当天目标。**
